# 数据时效性缺陷修复（2026-09-30）

## 用户发现的问题

闵行区试跑报告引用"2024年GDP"，但当前日期是2026年，报告全文没有任何地方说明这是否是最新可获得的数据。

## 根因（代码审查，非猜测）

1. `_normalize_results` 把 Exa 返回的 `publishedDate` 字段直接丢弃，只保留 url/title/snippet。模型从未见过任何证据的发布时间。
2. `_search_query` 拼接的查询词（`"{地区} 招商 {阶段标签}"`）没有任何时效性约束，Exa 检索也没有传日期过滤参数，结果排序完全由 Exa 默认相关性决定，可能优先返回权重更高但更旧的官方年报页面。
3. `_SYSTEM_PROMPT` 和 `_STAGE_INSTRUCTIONS` 从未要求模型标注数据年份，也没有告诉模型"今天是哪一天"，模型没有任何依据判断一条数据是否过时。

三者叠加：证据检索不筛新旧，证据展示不带日期，提示词不要求判断时效——报告自然不会主动提示数据可能过时。

## 修复（三层，写测试驱动）

1. **检索层**：Exa 搜索请求新增 `startPublishedDate`（当前日期减730天），只召回近2年内发布的证据。Brave 协议不支持此参数，未改动。
2. **证据展示层**：`_normalize_results` 保留 `published` 字段（映射 Exa 的 `publishedDate`），缺失时显式标注"发布日期未知"而非静默丢弃；`_build_messages` 把每条证据的发布日期展示给模型。
3. **提示层**：系统提示词新增"当前日期：YYYY-MM-DD"（真实系统时间，非硬编码），并要求"引用任何具体数据时必须标注该数据对应的统计/发布年份……优先采用最新可获得年份的数据，若最新证据本身年代已久（例如超过2年），必须在结论中明确指出"该数据可能非最新，需以官方最新发布复核"。

## 真实验证

对闵行区真实调用 `economy` 阶段：
- 检索结果全部在近2年内（2025-02 至 2026-06），此前未加过滤时曾引用2024年数据无任何提示。
- 模型输出主动写出"当前日期（2026-09-30）"，对每条引用数据标注统计年份，并做时效性判断，例如：\"2024年数据……距当前约1.5年，属可接受时效范围，但2025年全年数据尚未在给定证据中出现，2025年GDP总量及增速待核实\"；同时区分了"目标值"与"实际完成值"（此前的输出未做这层区分）。

## 结论

之前两次试点（松江、闵行）产出的报告都存在这个缺陷：引用具体数字但完全不提示时效性。这不是"数据造假"，而是"流水线没有告诉模型要主动核对新旧"，属于设计遗漏，现已在检索、展示、提示三层同时收紧。测试新增6项（`DataFreshnessTests` 5项 + Exa `startPublishedDate` 参数1项），121项全量测试通过。
