# 独立报告引擎与生产接入

本引擎复用现有 `report_service`，完全不调用 Violoop、Agenda、桌面设备或用户绝对路径。生产研究只使用 live provider；合成内容仅用于隔离测试，不能写入网站或知识库。

## 保留的业务合同

1. 经济、人口、交通土地园区、生活配套、产业方向、区域竞争、政策七类基础调研。
2. 产业链全景及本地已具备、缺失、薄弱环节。
3. 根据产业方向与缺口开展三个方向的企业调研：每方向至少25个候选，standard至少15个最终企业、deep至少25个最终企业。模式随任务定义持久保存，重试不能改变；深度模式分五批、每批5家检索和核验，避免扩大单次研究调用。落地状态、扩产来源、发布日期和不确定性显式保存。未知事实不能写成确定结论。
4. 经济、政策及高星企业信号的独立交叉核验；匹配分数由 Python 按既有权重计算，风险反向计分。
5. 行动计划、领导摘要、精简报告。共16份 Markdown，standard有77个、deep有83个持久研究子步骤，再独立构建交付包。
6. 完整与精简 Word 保持仿宋、公文字号、1.5倍行距、页边距及既有章节顺序；19个载荷的清单保存大小与 SHA256。
7. RAG主题仍为主导产业与产业链、园区与承载条件、链主与存量企业、政策规划。每主题最多60条；总数不足40不发布。精简正文写入 REPORTSTATE。

出处：`HUIXIAOZHAO_REPORT_SKILL.md`、`full_contract.py`、`word_export.py`。行数、来源数量和模型交叉核验属于门禁，不能当作事实正确的证明。公开知识库仅能接受真实完整报告。

## 运行和恢复

`server.py` 启动一个受监督的 `python -m report_service.hosted` 子进程，无需新增云服务。多个副本共享已有 PostgreSQL，由事务锁和有期限的租约控制唯一有效认领。研究调用在可终止子进程内，单次有硬截止；失效 worker 无权写检查点或完成。

独立镜像 `Dockerfile.full-report` 也使用 hosted 入口，默认配置关闭；不再默认启动合成报告 worker。本次不会创建或部署额外收费服务。

研究结果、尝试、失败事件、进展时间、下一次退避时间和最终文件全部持久存数据库。云端临时盘只用于构建文件；数据库存齐并校验载荷后才可以确认完成。重启后从已提交的子步骤继续；下载不依赖旧临时目录。外部调用不保证恰好一次，已经提交的检查点不会因为交付失败重做。

网络中断不能继续获取外部资料，但任务不会被假标为成功或丢弃；连接恢复后从检查点接续。暂时性错误持续退避，无总次数/累计时间放弃策略。失效认证与配置错误明确失败并保留成果，需要修复后运维恢复。

运维配置只读检查：`python -m report_service.hosted --check`（不连数据库、不检索、不调用模型，仅输出缺少的配置名）。修复配置后可用 `python -m report_service.hosted --resume-request rr申请ID` 恢复该申请；保留所有已完成检查点。取消或完成的报告不能通过该命令复活。

取消/重置在下一次租约检查终止本地研究子进程；远端已接受的请求可能仍计费。取消不删除已保存研究成果，也不会发布取消后的报告。

## 网站兼容

沿用 REPORT_REQUESTS、现有申请/取消/下载接口以及“推送到RAG”按钮。内部适配器使用固定网站队列隔离标识，不向前端引入服务凭据，不增加公开生成API。它不是新的用户身份系统；既有网站鉴权问题不由本改动解决。

新引擎的进度、城市及文件由服务器管理，旧消费者和旧浏览器快照不能通过 `/api/sync` 改写。既有完成报告保持原字节；原 running 报告不被自动重建、导入或伪装完成。RAG发布在单次事务中完成项目、城市基础包指针、正文和回执写入，重复请求不重复发布，不新建账号或密码。

报告完成与知识库发布分开重试；某报告交付异常不会阻止其他报告研究。REPORTSTATE的 score 来自核验一致项比例，既不是任意固定百分比，也不是事实可信度认证。

## 生产配置与切换

默认关闭，须通过环境变量明确启用：`HXZ_REPORT_ENGINE=standalone`、`HXZ_ENABLE_LIVE=1`。

现有 DATABASE_URL 复用。已有 DEEPSEEK_API_KEY 在内存中适配为模型配置，不复制、输出或创建凭据。也支持显式 HXZ_MODEL_URL/HXZ_MODEL_KEY/HXZ_MODEL_NAME。

真实检索需要 `HXZ_SEARCH_KEY` 和所选 Brave/Exa 配置；已有 EXA_API_KEY 可在内存中适配。必须是可用的独立检索连接，不能仅依靠模型记忆或从桌面凭据库搬运密钥。检索结果保存发布日期及实际检索时间。

在启用前确认旧消费者不再执行新申请，并用隔离真实城市报告验证来源、企业真实性、时效、Word可读性和发布。服务器写入保护不能证明外部旧任务已停止，也不能阻止其在自己的环境中继续消耗模型费用。

当前生产只确认配置了 DATABASE_URL、DEEPSEEK_API_KEY、GITHUB_TOKEN；没有确认可用的独立检索配置。因此本补丁不启用 live、不启动付费研究、不声称已经完成独立生产切换。既有报告仍由旧接口可下载。

## 验收证据

隔离测试分别验证：队列提交与重试、取消和旧状态写入保护、半包/合成发布拒绝、发布失败与幂等恢复、单个交付失败不阻止其他任务；PostgreSQL CI验证20并发认领、租约失效和重启接续、取消吊销、临时盘丢失后的19载荷下载及篡改拒绝。

这些故障测试证明流程和数据保护，不能替代真实来源验收。真实生成、持续检索配置与旧消费者退出仍是正式启用的必需条件。
