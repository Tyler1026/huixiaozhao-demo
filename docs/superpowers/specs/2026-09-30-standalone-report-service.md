# 独立报告服务：隔离试点

## 授权与边界

用户同意尝试将报告生产脱离 Violoop，并修改代码。基线 main 9776ad0；独立分支 feature/standalone-report-service。保留 identity 分支的未提交工作，不修改生产数据、网站入口、旧 Agenda 或外部流水线脚本。本轮不部署、不推送、不调用付费模型。真实研究和切换生产需要单独确认。

## 目标

独立 Python 进程提供任务 API 与 worker，不引用 Violoop 工具。提交、认领、阶段执行、状态和输出持久化；失败有明确状态，租约过期可接管，旧 worker 不能覆盖新结果。先在单机 SQLite 上验证这些语义；这不是 PostgreSQL 多实例生产验收。

## 模块

- store：事务化任务存储、幂等、租约、阶段结果与恢复。
- api：受服务令牌保护的 POST /reports、GET /reports/{id}；租户来自服务端配置，不信任调用方任意指定。
- worker：程序控制阶段依赖、心跳与结果提交；模型没有数据库发布权限。
- providers：显式 synthetic 测试模式；显式开启后可用直接模型 API 和搜索 API，失败关闭，不自动降级生成假资料。

## 研究试点

顺序阶段：经济、产业方向、竞争、政策、产业链缺口、目标企业、核验、评分、行动、报告。不同阶段使用不同职责提示词，后续引用前序结果。试点不是原 14-Agent 流水线的完整质量平价版本：暂不实现原有全部分面调研、三方向并发企业猎手、复杂 Word 和城市包自动发布。

联网适配器仅支持受控搜索结果证据，不把搜索摘要称为原文核验。外部文本为不可信证据，不能改变系统指令。综合阶段只使用持久化前序结果。所有合成产物显式标记不是研究报告。

## 安全与运行

API 默认 loopback。令牌从环境变量注入，不写入仓库。任务按服务端租户范围读取。输入和请求体有上限。模型及检索必须显式配置，HTTPS、超时、响应上限；错误不泄漏密钥。worker 只能用有效租约提交，失败或过期不能伪装成功。

SQLite 文件必须位于持久本机磁盘；不宣称可用于多个容器的共享网络文件系统。正式上线需 PostgreSQL 原子认领、组织身份集成、限流、对象存储、独立监控与备份、云端重启验收。

## 验收

1. 无 Violoop 运行时依赖的 CLI API 与 worker 可启动。
2. 临时数据库中提交报告，通过 worker 完成阶段并读回产物。
3. 同幂等键同载荷返回同任务；不同载荷冲突。
4. 并发 worker 不同时认领同一有效任务；租约过期后可恢复；旧租约不能提交。
5. 失败有可见状态且不暴露原始异常。
6. 合成测试不访问互联网；模型请求用注入的受控 transport 验证协议，不伪称真实研究验收。
7. 原站回归和前端构建不受影响。

## 生产切换前仍需完成

模型供应商/费用预算确认；真实城市研究端到端质量验收；原文来源抓取与质量门禁；PostgreSQL 部署；身份/组织授权；Word与对象存储；人工审核后的城市包发布；新旧队列单一消费者切换和回滚演练。
