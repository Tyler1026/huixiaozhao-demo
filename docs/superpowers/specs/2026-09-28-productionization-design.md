# 慧小招生产化设计：已批准方向与实施边界

## 用户已确认

- 统一网站，为不同客户开通账号。
- 先收集问卷，据用户所需城市提前准备城市包，避免首次进入空数据。
- 使用邀请码开通。
- 以客户组织隔离私有数据，同城不同组织不共享私有资料。
- 保持现有系统可用，采用渐进替换，不一次性重写。

## 领域边界

组织是租户边界；用户通过成员身份访问组织。工作区绑定城市与一个已发布城市包版本。客户上传资料、问卷、聊天、报告、确认与招商记录属于组织，不得反向写入公共城市包。城市包新版本不得无提示覆盖客户修改。

邀请绑定组织、角色、有效期和兑换次数，在服务端原子兑换；邀请不是长期登录凭证。城市包验收和工作区准备完成之前不得进入正式工作区。

## 目标开通链路

问卷申请 → 管理员审核 → 城市包生成任务 → 自动校验与人工验收 → 工作区准备 → 邀请 → 注册及组织绑定。

任务失败保持准备中并提供管理员可见原因。重复问卷或重试不能隐式重复创建客户空间。邀请重放不得重复创建成员。

## 工程路线

模块化Python单体与PostgreSQL。先补测试、失败语义和恢复基线，再引入服务端身份与组织校验，再按对象迁移整库同步。前端先分离API与业务模块，页面逐步迁移，不将框架重写与数据库迁移同时发布。

每类数据在迁移期间只能有一个权威写入口。新增兼容结构在先，切换读写在后，删除旧结构在最后。回滚应用不得通过覆盖数据库丢弃新客户写入。

## 第一批代码范围

在隔离worktree内修复无效同步载荷继续写入、读取失败覆盖、上传写入失败伪成功，以及提交需求未确认就显示成功。建立标准库回归测试与CI命令。记录外部流水线依赖。

SSE失败语义涉及多个旧消费者，必须前后端一并测试，不能只加error事件后假定客户端会处理。未经完整验证不得宣称本项完成。

## 发布门槛

- 两个同城组织的所有私有对象无法交叉读写。
- 存储失败、超时和冲突有明确可见状态。
- 备份在独立环境恢复成功。
- 工作区刷新和多用户并发测试通过。
- 城市包生成脚本改用受控服务身份，不因鉴权切换断流。
- 首次开通拥有正确城市资料。
- 部署、凭证轮换和生产迁移前单独确认。

## 本次未授权实施的事项

生产部署、生产数据迁移、凭证轮换、修改外部定时脚本、公开注册、发送邀请码。当前只进行本地第一批代码修改和合成数据验证。
